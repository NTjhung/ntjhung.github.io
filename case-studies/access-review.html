Project Summary

This project demonstrates an Identity Governance access review process using Microsoft Entra ID. The lab includes both a manual access review simulation and a live Microsoft Entra access review after Microsoft Entra ID P2 trial access was enabled.

The project simulates how an IAM team can review user access, collect reviewer decisions, track remediation, and prepare audit evidence.

Business Problem

Organizations need to regularly confirm that users still require access to sensitive systems, groups, and applications. Without regular access reviews, users may keep access they no longer need, which increases security, compliance, and audit risk.

Contractor access is especially important to review because contractor accounts may be temporary, project-based, or time-limited.

What I Built

  • Created a live Microsoft Entra access review.
  • Reviewed access for the SG-Contractors group.
  • Assigned a reviewer to evaluate contractor group access.
  • Documented reviewer decisions.
  • Approved one contractor user who still required access.
  • Denied one contractor user whose access was no longer required.
  • Created remediation tracking documentation.
  • Created a risk matrix and audit evidence packet.
  • Captured screenshots as audit evidence.

Documentation Summary

Review Scope

The review evaluated whether users still needed access based on department, job role, contractor status, privileged access risk, business need, and least privilege.

Review Decision Options

Decision Meaning
Approve User still needs access.
Deny / Remove User no longer needs access.
Review Further More information is needed before deciding.

Remediation

Remediation is the process of removing, updating, or correcting access after a review decision. In this lab, one contractor access assignment was identified for removal.

Testing Approach

  1. Open Microsoft Entra access reviews.
  2. Create a resource review for a group.
  3. Select SG-Contractors as the reviewed group.
  4. Assign a reviewer.
  5. Complete review decisions.
  6. Approve access that is still needed.
  7. Deny access that should be removed.
  8. Review results and remediation options.
  9. Capture screenshots as audit evidence.
