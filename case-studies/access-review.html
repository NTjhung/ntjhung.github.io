Project Summary

This project demonstrates a manual identity governance access review process. The lab simulates how an IAM team can review user access, collect reviewer decisions, track remediation, and prepare audit evidence.

This project does not require Microsoft Entra ID P1 or P2 licensing. Instead of using the built-in Microsoft Entra access review feature, this lab uses a manual review process based on group membership review, reviewer instructions, decision tracking, remediation documentation, and audit evidence.

Tools and Concepts

Business Problem

Organizations need to regularly confirm that users still require access to sensitive systems, groups, and applications. Without regular access reviews, users may keep access they no longer need, which increases security, compliance, and audit risk.

A repeatable access review process helps reduce excessive permissions, supports least privilege, documents reviewer decisions, and gives IT teams evidence that access is being reviewed and corrected.

Why It Matters

  • Reduces unnecessary or outdated access
  • Supports least privilege and access hygiene
  • Creates evidence for audits and compliance reviews
  • Identifies privileged access that needs validation
  • Tracks remediation when access should be removed
  • Helps standardize access review decisions

  • Created reviewer instructions for approving, removing, or escalating access.
  • Created sample access review data.

Review Scope

The review evaluated whether users still needed access based on department, job role, contractor status, privileged access risk, business need, and least privilege.

  • HR group access
  • Finance group access
  • IT Admin group access
  • Contractor group access
  • Privileged access risk
  • Business need and least privilege

Review Decision Options

  • Approve: User still needs access based on role, department, or business need.
  • Remove: User no longer needs access or access no longer appears justified.
  • Review Further: More information is needed before approving or removing access.

Remediation Process

Access reviews are only useful if the team follows through on removal or follow-up decisions. This project includes a remediation process to document what should happen after the review.

  • Confirm reviewer decision.
  • Validate whether access is still required.
  • Remove access when no longer justified.
  • Document the removal action.
  • Save screenshots or reports as evidence.
  • Track unresolved items until completion.
