Project Summary

This project demonstrates a basic Identity and Access Management user lifecycle workflow using Microsoft Entra ID. The lab simulates how an organization can onboard users, assign group-based access, document access controls, and offboard users when access is no longer needed.

The goal was to show practical IAM work that maps to real business needs: creating users, assigning the correct access, documenting the access model, removing access during offboarding, and saving screenshots as audit evidence.

Tools Used

Microsoft Entra ID PowerShell Microsoft Graph CSV Security Groups Audit Evidence

Business Problem

Companies need a repeatable process for onboarding, updating, and offboarding users. Without a consistent process, users may receive incorrect access, keep access longer than needed, or create audit and security risks.

A good IAM process helps reduce unnecessary access, supports least privilege, improves audit readiness, and gives IT teams a clearer way to prove that access was assigned and removed correctly.

Why It Matters

  • Reduces access mistakes during onboarding
  • Supports group-based access control
  • Improves offboarding consistency
  • Creates evidence for audits and reviews
  • Helps enforce least privilege

Joiner Process

A joiner is a new employee or contractor who needs access. The process includes creating the user account, assigning department-based access, requiring MFA registration, and documenting the request.

  • Create or import the user account.
  • Assign the user to the correct department group.
  • Confirm the access matches the user’s role.
  • Require MFA registration.
  • Save screenshots or reports as evidence.

Mover Process

A mover is an existing user who changes roles or departments. The process includes reviewing current group memberships, adding new required access, and removing access that is no longer needed.

  • Review current group membership.
  • Identify new access needed for the new role.
  • Remove old access that is no longer justified.
  • Document the access change.
  • Save before-and-after evidence.

Leaver Process

A leaver is a user who leaves the organization. The process includes disabling the account, revoking sessions, resetting the password, removing group memberships, and saving evidence.

  • Disable the user account.
  • Revoke active sessions.
  • Reset the password if needed.
  • Remove group memberships.
  • Document completion of access removal.
  • Save screenshots or reports as audit evidence.
